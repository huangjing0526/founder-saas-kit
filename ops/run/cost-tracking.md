# 成本运营

> solo founder 最容易**裸奔**的就是成本：没有财务盯着，云账单和 token 花销自己悄悄涨，月底一看才发现一个忘关的实例烧了一整月。
> 这份 runbook 给你一套最低限度的成本纪律：**每月记一次、设上限、抓异常增长**。不做复杂财务，只做"别突然被账单吓到"。

---

## 追踪什么

三大块，缺一块就是裸奔的口子：

1. **云基础设施** —— 服务器 / 数据库 / 对象存储 / 流量（出网带宽常被忽略，却最容易暴涨）。栈中立（示例：云主机 + 托管数据库 + 对象存储 + CDN）。
2. **AI / API token 花销** —— solo + AI 模式下这块**最容易失控**：一个写错的循环、一段没加上限的批处理，能在几小时内烧掉平时一个月的量。**必须单独一行追踪，不能混在"其他"里。**
3. **第三方服务订阅** —— 邮件 / 短信 / 监控 / 错误聚合 / 鉴权 / 各类 SaaS 月费。单个不贵，叠起来常是隐形大头；还容易留着"试用时开了再没用"的僵尸订阅。

---

## 怎么追

- **每月记一次。** 月初花 10 分钟，把上面三块各项的上月实际花销抄进台账（模板见底部）。**坚持记，比记得准更重要**——有连续数据才看得出趋势。
- **设预算告警阈值。** 在云平台和 API 平台上设消费告警（示例：达到月预算 50% / 80% / 100% 各推一次通知），别等月底账单才知道。token 平台同理，能设硬上限就设硬上限。
- **抓异常增长。** 每月对比上月，**任何一项环比异常上涨都要当场查清楚**，常见元凶：
  - 忘关的实例 / 测试环境跑了一个月没人停；
  - 失控的 token 调用（死循环、重试风暴、忘了关的 debug 全量调用）；
  - 流量异常（被刷、爬虫、没做缓存）；
  - 僵尸订阅（早不用了还在月扣）。

---

## 成本红线

- **设月度上限，超了先停下查。** 给整体和"最容易炸"的 token 这块各定一个月度上限。**触顶不是"加预算继续跑"，是先停下来查为什么**——失控的花销九成是 bug 或忘关，不是真实增长。
- **PRD 里成本写金额，不写次数。** 涉及成本的需求（"每个用户每天可以调用 N 次 AI"），落 PRD 时**换算成钱的上限**写，别只写次数。
  - 呼应 PRD Big-N 踩坑：只写次数时，单价一变 / 用量一超，成本就脱离掌控；写成金额上限，成本天花板才是钉死的。
  - 例（示例）：与其写"每用户每天 100 次 AI 调用"，不如写"单用户 AI 月成本上限 ¥X，达到即降级/限流"。
