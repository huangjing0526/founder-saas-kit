# 生产事故响应 runbook

> 出事时，**最该控制的不是 bug，是你自己**。
> 核心理念呼应项目宪法 P2「报错即停」：**出事别慌着自己乱救**——先想清楚，再动手。慌乱中连环改，往往把一个小事故改成大事故。

---

## 第一原则：止血优先，别在没想清楚时连环改

事故发生时，按这个顺序，不要跳：

1. **先评估影响面，不要先碰代码。**
   - 谁受影响？全部用户 / 部分用户 / 单个租户？
   - 受影响的是核心路径（登录、付费、写数据）还是边缘功能？
   - 数据有没有在持续被写坏？（如果是，**先停掉写入入口**，止血优先于查根因。）

2. **先决定要不要回滚，再决定怎么修。**
   - 上一个已知可用的版本是什么（commit sha）？回滚能不能立刻止血？
   - **能回滚就先回滚**——把用户从故障里捞出来，再慢慢查根因。让用户继续踩故障去等你查 bug，是新手最常见的错。
   - 回滚的红线（带回滚点、报错即停）见 ⑦ 部署：[`../../lifecycle/7-deploy/`](../../lifecycle/7-deploy/)。

3. **同一问题修第 3 次还在出 → 立刻停下。**
   - 这不是"再试一次就好"的信号，是**方向错了**的信号。
   - 停手，回到现象本身重新看，或者直接回滚到稳态，把"边修边炸"的循环掐断。
   - 这条和宪法 P2「报错即停，不自行重试 / 修复 / 回滚」是同一件事：**没想清楚时，每一次改动都在加大爆炸半径。**

---

## 事故分级与响应时限

按"影响面 × 严重度"分三级。级别决定你**多快必须有第一个动作**，以及第一个动作是什么。

| 级别 | 判断（满足任一） | 第一动作时限 | 标准动作 |
|------|----------------|------------|---------|
| **P0 — 全挂** | 服务整体不可用 / 全部用户登录失败 / 数据在被持续写坏 / 付费链路断 | **立即**（放下手头一切） | 优先回滚到上一稳态止血；停掉正在写坏数据的入口；同步通知用户 |
| **P1 — 核心功能坏** | 某个核心功能不可用但服务整体还在（如核心列表打不开、保存失败），影响多数用户 | **30 分钟内** | 判断回滚 or 热修；定位受影响范围；准备给用户的说明 |
| **P2 — 局部** | 边缘功能异常 / 个别租户 / 个别场景报错，多数用户无感 | **当天内** | 记录现象，排进当天修复；无需紧急回滚；无需大范围通知 |

> 一个人做产品，没有 on-call 轮值。**分级的意义是帮你判断"现在该不该放下别的事"**——P0 放下一切，P2 别打断自己的节奏去过度反应。

---

## 标准动作（六步，按顺序）

1. **确认现象** —— 自己复现一遍，确认"真的坏了"以及"坏成什么样"。别凭一条用户反馈就开始大改。记下：什么操作、什么报错、影响谁。
2. **看监控 / 日志** —— 拉错误监控（示例：错误聚合服务）和应用日志，定位错误最先出现的时间点。**把它和最近一次部署 / 改动对齐**——事故九成跟"最近改了什么"有关。
3. **判断回滚 or 修复** —— 能快速回滚止血就回滚（P0 默认回滚）；只有当根因明确、改动极小、风险可控时才选热修。**拿不准就回滚**，回滚永远比带病热修安全。
4. **执行** —— 回滚走部署红线流程（先记回滚点、报错即停）。热修同样守 P1-P3：方案想清楚再连续执行，任何一步报错就停下。
5. **记录时间线** —— 从发现到恢复，每个关键动作记一行时间戳（用下方模板）。**事中顺手记，事后补不全。**
6. **恢复后写复盘** —— 服务恢复 ≠ 结束。把根因和改进写进复盘，喂回流程，避免同坑再踩。复盘进 ⑨：[`../../lifecycle/9-retrospective/`](../../lifecycle/9-retrospective/)。

---

## 沟通：出事时怎么跟用户说

事故里**沉默比 bug 更伤信任**。用户能接受偶尔出问题，不能接受"出了问题没人理"。

- **早说，哪怕信息不全。** "我们发现 X 功能异常，正在处理，会持续同步"——比闷头修两小时强。
- **说影响和预期，不说技术细节。** 用户要知道的是"我的数据安不安全 / 大概多久好"，不是你的堆栈。
- **别承诺具体分钟数**，除非你真有把握。说"正在定位"好过说"5 分钟后好"然后失约。
- **恢复后补一条**："已恢复，原因是 X，我们做了 Y 防止再发生。" 这条比道歉更能挽回信任。
- 通知渠道栈中立（示例：站内公告 / 邮件 / 群通知），提前选好一个，别等出事现找。
- 发布 / 恢复公告的写法可沉淀成模板，放本目录（同级 [`./`](./)）复用。
