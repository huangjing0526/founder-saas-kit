# 无人值守与 Handoff

> AI 自主跑（定时任务 / 异步 / CI 响应）和「你坐在旁边盯着」是**两种风险等级**。
> 没人实时阻止它时，AI 更要保守——这份文档定义自主场景下的交接协议：
> **开跑前确认什么 · 跑的过程留什么痕迹 · 跑完怎么交给人 review · 额外硬约束 · 报错即停。**

---

## 1. 适用场景

AI 在没人盯着的情况下推进工作，主要三类：

- **定时任务**：固定节拍自动跑（如每天早间生成日报、夜间批处理）。
- **异步响应**：响应外部事件触发（如 issue / PR 里被 @ 提及后自行开工）。
- **CI 响应**：在持续集成流水线里自动执行（构建 / 测试 / 部署的某一环）。

这三类的共同点：**人不在现场，无法实时叫停**。所以它们比交互式开发多一层约束。

---

## 2. 开跑前确认什么

自主任务启动前，先把「能不能跑、跑成什么样算对」确认清楚，不靠猜：

1. **需求清不清楚**：不清楚就**先提问、不开工**——异步场景下别直接开 PR 猜需求。在 issue / 触发源里留言问，等回复。
2. **风险等级**：看任务标签 / 描述判断是不是高风险（碰数据库结构、删数据、生产部署、改单点冲突文件）。高风险任务即便能自动跑，也应停在「出方案」这一步等人确认。
3. **回滚点**：任何会改动持久状态（代码 / 数据库 / 生产）的任务，开跑第一件事是记录回滚点——当前的 commit 标识、进程管理器(pm2/systemd) 当前状态；涉及数据库变更先确认备份存在。
4. **任务拆分**：长任务先拆成 step，**每个 step 一个 PR**，不要一个 PR 干所有事——这样人 review 时能逐段看、能逐段挡。

---

## 3. 跑的过程留什么痕迹

无人值守的命门是「**事后能复盘**」。AI 自主跑时，每一步都要留可审计的痕迹：

- **每步命令 + 输出可见**：执行了什么、返回了什么，清晰记录，保证可审计。
- **关键节点写日志**：进度、判断、为什么这么选，都落在能被人翻到的地方（日志文件 / PR 描述 / 交接文档）。
- **后端出错先记上下文再抛**：日志里带上是谁、哪个租户、做什么动作（`userId / tenantId / action`），别静默吞掉错误。
- **改动范围克制**：只动当前任务相关的文件。看到任务之外的改动（尤其数据库 schema / 迁移 / 路由这类**单点冲突文件**），默认它属于别的并发会话，不要打包进来。

> 并发的多个 AI 会话可能同时在跑，互相覆盖改动。提交前必须先看清暂存内容、**只暂存当前任务相关文件**——绝不全量 stage（`git add .`），绝不把 add + commit + push 链成一条命令。

---

## 4. 跑完怎么交给人 review

自主任务跑完不等于「完成」，而是「**进入待 review 状态**」。交接物要让人在手机上就能 review：

| 交接物 | 内容 |
|--------|------|
| **PR 描述 / 完成通知** | 假设人在手机上 review：要点写最上面，diff 之外的事讲清楚（为什么这么改、影响面、最可能在哪出问题）。 |
| **大白话上线说明** | 改了什么 / 影响哪些用户 / 出问题最可能在哪——不用代码术语。 |
| **回滚依据** | 回滚点的 commit 标识、备份位置，写在交接里，意外时能照着回滚。 |
| **未尽事项 / 下一步** | 没做完的、需要人决策的，列清楚，别藏在 diff 里。 |

### Handoff 文档（跨会话接力）

多会话 / 隔夜接力时，离开前写一份 Handoff，下次任意会话读了就能接手。推荐结构：

| 小节 | 必填 | 说明 |
|------|------|------|
| **当前进度** | 是 | 做到哪一步；改动了哪些关键文件 / 模块。 |
| **下一步（1～3 条）** | 是 | 接下来要做的具体事项，每条可对应一个子任务。 |
| **谁来做** | 是 | 对应角色（见 [ai-agent-roles.md](./ai-agent-roles.md)）：主 agent 自己接，还是派某个子 agent。 |
| **验收标准** | 建议 | 每步完成的判定条件。 |
| **已改动关键文件** | 可选 | 便于续写 / 排查时快速定位。 |

> Handoff = **单次交接**（当前进度 + 下一步）。
> 跨会话的「记忆」另有 session 三件套（save / resume / clean）兜底——见同级 [`../collaboration/session-commands/`](./session-commands/)。

恢复时的唤醒话术示例：

> 「请先读最新的 handoff 文档，按里面的『下一步』和『谁来做』继续。」

## 5. 自主场景的额外硬约束（没人实时阻止时更要保守）

交互式开发里人能随时喊停，自主场景没有这层保险。所以**自主跑时约束要更紧**：

1. **不清楚就停下问，不要猜着开工**——交互式可以边做边对齐，自主场景一旦猜错没人当场拦。
2. **高风险任务即便能自动跑也停在方案**——碰数据库结构 / 删数据 / 生产部署，自主场景下只出方案，等人确认。
3. **破坏性操作永远要单独确认**——删表 / 删列 / 删生产资源 / 对受保护分支强推，不在「方案确认后连续执行」的范围内，必须单独点头。
4. **不自行修复、不重试、不自愈**——见 §6。
5. **改动范围更克制**——并发会话风险在自主场景下更难发现，绝不碰任务之外的文件。

> 一句话：**人不在场，就把「该问的问到、该停的停下、该留痕的留全」做到比平时更足。**

---

## 6. 报错即停

这是自主场景下**唯一不容商量**的铁律：

- **任何一步失败立即停**：构建失败 / 测试失败 / 部署失败 / 健康检查失败 / 迁移报错 / 拉取冲突——立即停止，**不自行尝试修复、不重试、不切换方案、不回滚**。
- **停下后汇报四件事**：
  1. 失败的**具体命令**；
  2. **原始错误输出**（至少关键行）；
  3. 当前**服务状态**（进程状态 / 健康检查结果）；
  4. 可用的**回滚点**（commit 标识、备份位置）。
- **等人决定下一步**：回滚 / 人工介入 / 换方案，由人拍板。

> 为什么不让 AI 自愈：自主场景下一旦自愈方向错了，会在没人知道的情况下越修越偏，把小故障放大成事故。**报错即停 + 完整汇报**，把决策权交回给人，是无人值守最重要的安全阀。

---

## 一句话记住

> 自主跑 = 没人当场拦的开发：开跑前把需求 / 回滚点 / 拆分确认到位，
> 跑的过程留全可审计痕迹，跑完进「待 review」而非「已完成」，
> 比平时更保守，**报错即停、绝不自愈**。
