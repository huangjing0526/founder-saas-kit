# 上手协议（Onboarding）

> 新会话 / 新人 / 新 AI 进项目，最怕「上下文靠口口相传」——问东问西、各自理解不一、关键约束没人讲。
> 这份文档把「第一天该读什么、按什么顺序读」做成一个**可复制的上手协议**：
> 任何人 / 任何 AI 照着走一遍，就能进入状态，不依赖谁在旁边带。

---

## 1. 为什么要有「上手协议」

一个人带着 AI 长期做产品，会反复遇到「冷启动」：开个新会话、换台机器、换个模型、或真有新人加入。每次都靠现讲一遍背景，既慢又容易漏。

上手协议解决的是：**把「进入状态需要的上下文」固化成一个固定加载顺序**，而不是散落在脑子里、靠临场回忆。好处是——

- 新 AI 会话开场第一句就能自我装载，不用你重述项目。
- 真有新人时，给一份文档就能自己上手。
- 你自己隔几周回来，也照同一条路径快速找回状态。

---

## 2. 上下文加载顺序（核心）

无论是人还是 AI，进项目按这个顺序过一遍。**先宪法、再背景、再当下、再反馈**：

| 顺序 | 读什么 | 为什么先读它 |
|------|--------|--------------|
| 1 | **项目宪法** [`../../.claude/CLAUDE.md`](../../.claude/CLAUDE.md) | 优先级最高的协作铁律——红线、Git 规矩、生产操作规矩、输出前自检。先立规矩，再干活。 |
| 2 | **项目背景 / 简报** | 这是什么产品、给谁用、技术栈、架构骨架——建立全景。 |
| 3 | **当前 sprint** | 这一轮在做什么、优先级是什么——知道「现在该往哪使劲」。 |
| 4 | **反馈 / 待办** | 用户反馈、积压问题——知道「真实痛点在哪」。 |

> 这四层是「**由稳到动**」：宪法几乎不变 → 背景偶尔变 → sprint 每轮变 → 反馈每天变。先读稳的（建立框架），再读动的（填入当下），上下文才不会乱。

AI 新会话开场可以直接说：

> 「按上手协议加载上下文：先读项目宪法 `.claude/CLAUDE.md`，再读项目背景、当前 sprint、反馈待办，然后等我指示。」

---

## 3. 第一天该读哪些（按角色加深）

加载完 §2 的四层框架后，按你的角色挑对应的「技术规范」深读。下面的模块是**示例，按你的业务换**：

### 通用（所有角色）

- **协作流程**：日常怎么配合（仓库、分支 <dev>/<main>、提交约定、部署节奏）。
- **架构核心规范**：字段配置、数据模型映射、多语言协议、UI 布局准则。
- **常见陷阱**：项目里反复踩过的坑（写出来就不用每个人再踩一遍）。

### 前端

- **UI / 交互规范**：列表、表格、弹层、空状态、无障碍——视觉与交互一致性的硬约束。
- **菜单与路由**：新页面归到哪组菜单、路由怎么配、权限怎么挂。

### 后端

- **数据权限模型**：数据范围（本人 / 本部门 / 全公司）怎么算。
- **多租户隔离**：查询怎么带租户过滤、软删除怎么处理、列表与统计怎么共用 where。（示例：`lead` / `customer` 这类业务模块的查询——**示例，按你的业务换**。）
- **安全原语**：data-scope filter / audit masking / input sanitize 这套封装怎么用。
- **后端分层**：Routes → Services → Repositories 的边界。

### 产品 / 测试 / 全栈

- **主 PRD**：功能规格全貌、已完成 / 待开发清单。
- **发版清单**：上线前要核对的项。

### AI 协作

- [`ai-agent-roles.md`](./ai-agent-roles.md) — 主 agent / 子 agent / 三个只读 reviewer / 人 的分工。
- [`unattended-handoff.md`](./unattended-handoff.md) — 自主跑 / 跨会话接力的交接协议。

## 4. 怎么不靠「口口相传」

上手协议能成立，前提是上下文**写在文档里、而非存在某个人脑子里**。三条做法：

1. **单一入口**：上手只认这一份文档作为起点（再由它指向别处），别让新人 / 新会话面对一堆零散链接不知从哪开始。
2. **过程同步，而非事后补**：改了代码立刻同步对应文档，别等任务结束——这样新人读到的永远是当前状态，不是三个月前的快照。
3. **新概念落术语表**：遇到项目内部黑话 / 新概念，沉淀进术语表（见同级 [`../decisions/`](../decisions/) 里的术语表），不靠「下次再口头解释一遍」。

> 判断上手协议有没有失效，有个简单信号：**如果新会话 / 新人还在反复问「这个为什么这么定」「那个在哪」，说明上下文还在某人脑子里，没落进文档。** 那就是该补文档的地方。

---

## 5. 本地跑起来（占位）

每个项目的启动步骤不同，这一节放你项目的实际命令。通用骨架：

1. 装依赖、复制环境变量样例为 `.env` 并填好数据库连接等。
2. 初始化 / 迁移数据库。
3. 启动开发服务，浏览器访问本地地址确认能跑起来。

> 把这三步换成你项目的真实命令，让任何人 / 任何 AI 照着就能在本地把应用跑起来——「能跑起来」是进入状态的最后一步。
