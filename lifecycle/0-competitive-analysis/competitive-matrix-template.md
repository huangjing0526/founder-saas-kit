## 填好的示例(虚构产品:给独立开发者的轻量记账 SaaS)

| 维度 | 我们(规划) | 竞品 A:某老牌财务软件 | 竞品 B:某通用记账 App | 替代方案:Excel + 银行账单 |
|------|------------|----------------------|----------------------|--------------------------|
| 目标用户 | 独立开发者 / 一人公司 | 中小企业财务 | 个人消费记账 | 所有怕麻烦的人 |
| 核心功能 | 自动归集收入 + 报税估算 | 全套账务 + 工资 + 库存 | 手动记每一笔 | 手填 |
| 差异化 | 对接 Stripe/支付平台自动入账 | 无(要手动导) | 无(纯手动) | — |
| 定价 | $9/月 | $50/月起 | 免费 + 内购 | 免费 |
| 免费档 | 50 笔/月 | 无,只有试用 | 基础功能免费 | — |
| 用户骂什么 | — | "太重、学习成本高" | "要手动记,坚持不下来" | "对账到崩溃、易错" |
| 护城河 | 自动化省时间 | 数据迁移成本高 | 弱 | 无 |

**三个结论**:
1. **差异化点**:自动对接收款平台,**不用手动记** —— 这是 A/B/Excel 都没解决的痛点。
2. **MVP 必含**:收入归类 + 报税估算(独立开发者最焦虑的两件事)。
3. **明确不做**:工资 / 库存 / 多人协作(那是竞品 A 的战场,不是我们的)。

**本次结论有效期**:下个报税季前复看(支付平台 API 政策可能变)。
