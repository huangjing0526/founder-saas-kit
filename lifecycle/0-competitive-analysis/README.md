# ⓪ 竞品分析

> 在动手做任何东西之前,先搞清楚:这块地上已经有谁、他们做得怎么样、你凭什么不一样。
> 这是产品生命周期的**最前端**——市场/研究环节,喂给①需求发现和②PRD。

## 这一阶段解决什么

- **别重新发明轮子**:你想做的功能,大概率有人做过——先看他们做成什么样、踩过什么坑。
- **找差异化**:你的机会往往藏在竞品的**缺口**里(他们没做好的、忽略的细分人群)。
- **定 MVP 边界**:看清"行业标配"和"差异化点",才知道**先做什么、不做什么**(避免"竞品有我也要有"的功能堆砌陷阱)。
- **给定价/定位提供锚点**:不是拍脑袋,是看着竞品的定价和定位来定自己的。

## 怎么走这一步

```
列竞品(直接/间接/替代) → 多渠道挖料 → 填对比矩阵 → 画定位图找缺口 → 得出 3 个结论
                                                                        │
                                                    ┌───────────────────┤
                                                    ▼                   ▼
                                          ①需求发现(差异化点)   ②PRD §技术/业务边界
                                          差异化喂进三层拆解      "不做什么"写进 PRD 范围
```

## 这一阶段的产物

1. **竞品对比矩阵**——功能 / 定价 / 目标用户 / 优劣势一张表(模板见 [`competitive-matrix-template.md`](competitive-matrix-template.md))
2. **3 个可执行结论**——不是"了解了",而是:① 我们的差异化点是什么 ② MVP 必须有哪些"行业标配" ③ 明确**不做**哪些(竞品做了但不是我们的战场)

## 上下游衔接

- **下游 ①需求发现**([`../1-discovery/`](../1-discovery/)):竞品缺口 → 喂进需求三层拆解的"真实目标/根本动机",找到你的差异化切入点。
- **下游 ②PRD**([`../2-prd/`](../2-prd/)):"不做什么"的结论直接写进 PRD 的范围/边界;差异化点写进 PRD 的目标与成功指标。
- **决策有真分歧时**(要不要正面刚大厂 / 走哪个细分):走多视角决策([`../../engineering/governance-skills/S11-multi-perspective-decision.md`](../../engineering/governance-skills/S11-multi-perspective-decision.md))。

> ⚠️ 竞品分析**不是一次性的**。每季度 / 每次大版本前快速复看一次——市场在变,你三个月前的结论可能已经过期(呼应防漂移:结论要有"何时复看"的时效)。
