# 依赖与安全更新节奏

> 一个人做产品，依赖最容易**裸奔**：装了一堆包，从此不管，直到某天一个 CVE 漏洞炸出来。
> 这份 runbook 给你一套**轻量但定期**的节奏：不追新潮，但不让已知风险一直挂在生产上。

---

## 为什么要定期管依赖

不管它，三种事迟早找上门：

- **CVE 漏洞** —— 你用的包被爆出安全漏洞（示例：某序列化库远程执行）。攻击者扫的就是"知道有洞还没补"的站。
- **供应链风险** —— 包的维护者换人 / 被注入恶意代码 / 依赖链里某个传递依赖出问题，你装的不只是直接依赖，还有它背后一整棵树。
- **lockfile 漂移** —— 锁文件和实际安装不一致、不同环境装出不同版本，"本地好的线上炸"很多时候根因在这。

---

## 节奏

不用天天盯，固定节拍就够：

| 频率 | 做什么 |
|------|--------|
| **每月一次** | 扫一遍依赖漏洞（示例：`npm audit` / 等价工具），把结果分级：高危马上处理，中低危记下排期。 |
| **随到随打** | 安全补丁（patch / 小版本里的安全修复）**及时打**——这类风险低收益高，别拖。 |
| **谨慎排期** | 大版本升级（major）有破坏性变更风险，**单独排期、单独测**，绝不和功能开发混在一个改动里。 |
| **每季度一次** | 清一遍"装了但没在用"的依赖——删掉减少攻击面，也呼应北极星的代码极简。 |

> 把"每月扫一次依赖"挂进 `cadence/` 的月度节奏里（[`../cadence/`](../cadence/)），别靠记性。

---

## 高危 CVE 处理

扫出高危时，先判断**要不要紧急修**，别一律连夜升级：

1. **判断真实暴露面** —— 这个漏洞触发条件是什么？你的代码真的走到那条路径了吗？
   - 比如漏洞只在"处理不可信上传文件"时触发，而你根本没这功能 → 风险实际很低，可正常排期。
   - 漏洞在核心依赖、且无需认证就能触发 → 紧急修。
2. **找官方修复版本** —— 优先升级到打了补丁的版本。直接依赖能升就升，跑一遍测试确认没炸。
3. **传递依赖：用 override（覆盖）兜底，但知道它有风险。**
   - 当有风险的包是某个直接依赖**间接**带进来的、上游还没发新版时，可以用包管理器的 override / resolutions 机制强制锁到安全版本（示例：`overrides` 字段）。
   - **override 的风险**：你是在替上游"赌"这个新版本和它兼容。上游没测过这个组合，**可能引入不兼容**。
   - 所以 **override 之后必须跑全套测试**，确认功能没退化；并在依赖里写一行注释说明"为什么 override、哪天可以撤"（等上游正式升级后撤掉）。
4. **改了 lockfile 一定重测。** 任何动了锁文件的操作（升级 / override / 重装），都当成一次有风险的改动：跑测试、本地验核心路径，绿了才提交。

## 红线

呼应 kit 北极星（[`../../engineering/methodology/north-star-rules.md`](../../engineering/methodology/north-star-rules.md)，"新增依赖前说明理由"）：

- **不引入新依赖，除非确认。** 加一个包前先问：标准库 / 已有依赖能不能做？真要加，**说清楚理由 + 评估维护活跃度和体积**，再决定。每多一个依赖，多一份供应链风险和升级负担。
- **锁定版本。** 提交 lockfile，部署用锁定版本安装（示例：`npm ci` 而非 `npm install`），保证各环境装出来一致。
- **来路不明的包不用。** 下载量极低 / 长期没维护 / 名字和知名包高度相似（typosquatting）的包，一律不碰——这正是供应链攻击的入口。

## 依赖更新检查清单

> 每次动依赖（月度扫描后处理 / 升级 / override）走一遍。

```markdown
## 依赖更新 — <YYYY-MM-DD>

### 扫描
- [ ] 跑了漏洞扫描（npm audit / 等价工具）
- [ ] 结果分级：高危 __ 个 / 中危 __ 个 / 低危 __ 个

### 处理
- [ ] 高危：逐个判断暴露面，决定紧急修 or 排期（记原因）
- [ ] 安全补丁：能打的都打了
- [ ] 大版本升级：单独排期，没混进功能改动
- [ ] override（如有）：写了原因注释 + 标了可撤条件

### 新增依赖（如有）
- [ ] 说明了为什么非加不可（标准库 / 已有依赖为何不行）
- [ ] 查了维护活跃度、下载量、体积，确认不是可疑包

### 验证
- [ ] lockfile 已更新并提交
- [ ] 跑了全套测试，全绿
- [ ] 本地验过核心路径没退化
```
