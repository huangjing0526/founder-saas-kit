# 数据迁移与导入

> 给非技术 founder：这份讲一个**容易被当成"技术细节"忽略、实则是获客生命线**的功能——**让客户能把已有数据搬进你的系统**（从 Excel、从竞品导出文件）。
> ⓪ 竞品分析里点过名：**"帮客户搬家"本身就是一条护城河。**
> 核心一句话：**一个客户决定不决定用你，常常卡在一个很土的问题——"我现在这一堆数据，能不能一键搬进去？"**

---

## 1. 为什么"导入"是获客手段，不只是技术功能

换一个软件，对客户来说最大的恐惧不是"学不会"，是**"我攒了几年的数据怎么办"**。

- 没有导入功能 → 客户要**手动一条条重新录入** → 大多数人到这一步直接放弃，你白白丢单。
- 有顺滑的导入 → 客户**几分钟搬完、立刻看到自己的数据在你这儿跑起来** → 转化率天差地别。

所以导入不是"做完核心功能有空再补的边角料"，它是**降低客户切换成本的获客武器**：

- **从 Excel 导入** → 接住那些还在用表格管业务的客户（量很大）。
- **从竞品导入** → 直接把竞品的用户挖过来——他们能一键搬家，离开竞品的成本就低了。

> 一句话：**别人搬家越省力，你的获客越省钱。** 把导入当成销售漏斗的一环，不是技术待办的末位。

---

## 2. 规划要点（founder 要确认这几件事被想到了）

导入功能要做得好，下面这几点必须被规划进去。你不用懂怎么实现，但要确认 AI / 工程师**每一条都有答案**：

| 要点 | 大白话 | 不做好会怎样 |
|------|--------|-------------|
| **支持什么格式** | 客户的数据从哪来？Excel（.xlsx）、CSV、还是竞品的导出文件 | 格式不支持 = 客户根本传不进来 |
| **字段映射** | 客户表格里叫"客户姓名"的那一列，对应你系统里的哪个字段 | 映射不灵活 = 列名稍微不一样就导不进 |
| **校验** | 导入前先检查数据对不对（电话格式、必填项有没有空、日期合不合法） | 不校验 = 脏数据直接灌进系统，后患无穷 |
| **回滚** | 导错了能不能一键撤销、退回导入前的样子 | 不能回滚 = 客户导错一次就毁了数据，再也不敢用 |
| **批量大小** | 客户一次传 10 万条会不会把系统搞卡 / 搞崩 | 不限制 = 大客户一导入就把服务拖垮 |

> 这五条里，**"校验"和"回滚"是 founder 最该盯的**——它们直接关系到"客户会不会因为一次导入事故就对你失去信任"。呼应 [`README.md`](README.md) founder 视角第 2 问：动数据的操作，必须能退回上一个好状态。

## 3. 对非技术 founder 的决策点：先做哪种导入

你不用决定"怎么实现"，但要决定**"先做哪种、做到多完善"**——这是产品取舍，该你拍板：

1. **先做哪个来源？** —— 看你的目标客户**现在数据都存在哪**。
   - 目标客户大多用 Excel 管业务 → **先做 Excel 导入**（覆盖面最广）。
   - 你在挖某个特定竞品的用户 → **优先做那个竞品的导入**（针对性挖墙脚）。
2. **第一版做到多完善？** —— 别追求一步到位。
   - 第一版可以**只支持最常见的格式 + 最核心的几个字段**，先让大多数客户能搬进来。
   - 复杂场景（一对多关系、附件、历史记录）等有客户真的要了再加。
   - 这正是 [`README.md`](README.md) founder 视角第 4、7 问的应用：**能拆小步就拆小步，先做半个验证有没有人用。**
3. **导入出错时给客户看什么？** —— 这是体验分水岭。
   - 好体验：明确告诉客户"第 37 行电话号码格式不对，请改后重传"。
   - 坏体验：一句笼统的"导入失败"，客户一脸懵、直接放弃。

## 4. 常见坑（这几个最容易让导入翻车）

- **编码问题（中文变乱码）**：客户的 Excel / CSV 用的字符编码和你系统不一致，导进来全是乱码（"客户名"变成一堆方块）。**这是最高频的导入投诉，必须在规划时就让工程师明确怎么处理。**
- **时区 / 日期格式**：客户表格里的"2026/6/5"到底是几号？不同地区日期写法不同（月在前还是日在前），处理不当日期全错。客户跨时区时，"创建时间"还会整体偏几个小时。
- **重复数据**：客户重复导入两次，或表格里本来就有重复 → 系统里冒出一堆重复客户。要先想清楚**"碰到重复怎么办"**（跳过 / 覆盖 / 提示客户选）。
- **必填项缺失**：客户的表格里某些你认为必填的字段是空的 → 要么导入失败，要么灌进一堆残缺数据。校验环节要明确**"缺了必填项是整批拒绝、还是跳过这几行"**。
- **大文件搞垮系统**：客户一次导几十万条，系统当场卡死或超时。要么分批处理，要么给一个明确的"单次最多 N 条"上限。

> 这些坑里**没有一个需要你懂代码**——你要做的是在规划时把这几个问题甩给 AI / 工程师，确认每一个都有应对方案。问不出答案的，就是该卡下来的地方。

---

## founder 速查清单（规划导入功能时过一遍）

- [ ] **先做哪个来源**：Excel 还是某竞品？依据是"目标客户的数据现在存在哪"。
- [ ] **格式**：支持客户实际在用的格式了吗（.xlsx / .csv / 竞品导出文件）？
- [ ] **校验**：导入前会检查数据对不对吗？错了会清楚告诉客户错在第几行吗？
- [ ] **回滚**：导错了能一键撤销、退回导入前吗？（动数据必须能回退）
- [ ] **重复数据**：碰到重复怎么处理，想清楚了吗（跳过 / 覆盖 / 让客户选）？
- [ ] **编码 / 时区**：中文乱码、日期格式这两个高频坑，工程师有明确方案吗？
- [ ] **批量上限**：大客户一次导几十万条会不会把系统搞崩，有保护吗？
- [ ] **第一版边界**：第一版只做最核心的格式 + 字段，能拆小步先上吗？

> 收尾：导入做得好不好，往往就是"客户当场成交"和"客户卡在搬家、悄悄走人"的分界线。它值得你像盯核心功能一样盯。
