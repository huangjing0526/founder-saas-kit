# 三态强制（Loading / Empty / Error）

> 一句话：**任何会异步取数据的列表 / 页面 / 组件，必须显式处理三种状态——加载中（loading）、没数据（empty）、出错了（error）。缺一态就是 bug，不是「以后再补」。**
> 框架无关。具体模板（实现示例）见 [`examples/ui-baseline.example.md`](../../examples/ui-baseline.example.md)。

---

## 1. 为什么三态是硬红线

异步取数有四种结局，UI 都得有交代：

1. **正在取** → 给反馈（骨架屏 / 转圈），否则用户以为卡死。
2. **取到了，有数据** → 正常渲染。
3. **取到了，但是空的** → 给空态（解释 + 引导），否则用户看到白屏以为坏了。
4. **取失败了** → 给错误态（说明 + 重试），否则用户看到白屏且无路可走。

少处理任何一态，用户就会撞上「永久转圈 / 白屏 / 不知道发生了什么」——这是 SaaS 里最高频的低级事故，而且**最容易被漏**：开发时数据总是有的，空态和错误态在本地几乎不会触发，于是没人写。所以它必须是**强制项 + 自检项**，靠纪律而非靠「想起来」。

---

## 2. 三态的判定（什么时候算哪一态）

用「是否在加载」+「有没有出错」+「数据是否为空」三个信号组合判定，**顺序很重要**：

| 态 | 判定条件（按优先级从上到下） | 展示 |
|---|---|---|
| **Loading** | 正在请求 **且** 还没有可显示的数据 | 骨架屏（首屏）/ 行内加载提示（加载更多） |
| **Error** | 请求结束 **且** 出错了 | 错误态：说明文案 + **重试**入口 |
| **Empty** | 请求结束 **且** 没出错 **且** 数据为空 | 空态：图标 + 标题 + 说明（+ 可选 CTA） |
| **正常** | 请求结束 **且** 没出错 **且** 有数据 | 渲染内容 |

> 判定顺序的坑：先判 empty 还是先判 error 会得到不同结果。**error 优先于 empty**——加载失败时数据当然也是空的，但要给的是「重试」而不是「去新建」。

**Loading 还要分两档**（列表场景）：
- **首屏加载**（`loading && 数据为空`）→ 骨架屏，禁止页面正中央放一个孤零零的转圈。
- **加载更多 / 刷新**（`loading && 已有数据`）→ 列表底部小字提示或顶部刷新指示，不要把已有内容也盖成骨架。

## 3. 每态的要求 + 反例

### Loading

- ✅ 首屏用**骨架屏**（撑出内容轮廓），让用户预期即将出现什么。
- ❌ 反例：列表正中放 `转圈 spinner` —— 用户不知道要等什么、等多久。
- ❌ 反例：加载更多时把整个列表重置成骨架，已读位置丢失。

### Empty

- ✅ **四件套**：图标 + 标题（短句）+ 说明（解释为什么空 / 怎么办，可选）+ CTA 按钮（引导下一步，可选）。
- ✅ 所有文案走多语言（i18n），禁硬编码任何语言。
- ✅ 用**统一的空态组件**，不要每个页面自画一个空图（见 [`component-reuse-redline.md`](component-reuse-redline.md)）。
- ❌ 反例：数据为空时整片白屏，用户以为页面坏了。
- ❌ 反例：每个列表自己画一套空态插图，五个版本各不相同。

### Error

- ✅ 给**人话错误文案** + **重试**入口（点了能重新请求）。
- ✅ 错误信息用统一兜底（如「友好错误信息」字段），**禁止把原始异常 / 英文堆栈直接甩给用户**。
- ✅ 操作型失败（提交、删除）用非阻塞提示（toast）；页面级加载失败用整页错误态。
- ❌ 反例：`catch` 到错误后什么都不做（吞掉），页面停在 loading 或白屏。
- ❌ 反例：把 `e.message`（可能是一串英文 stack）直接显示给客户。

> 「吞错误」与全局规则「Never silently catch and ignore errors」一致——错误要么展示给用户，要么记录上报，绝不静默丢弃。

## 4. 自检：三态齐了吗

写完任何异步列表 / 页面 / 组件，逐条回答：

- [ ] **Loading**：首屏有骨架屏？加载更多有独立提示（没盖掉已有内容）？
- [ ] **Empty**：数据为空时有空态四件套？文案走 i18n？用的是统一空态组件？
- [ ] **Error**：请求失败时有错误态 + 重试？错误文案是人话不是堆栈？没有静默吞错误？
- [ ] **判定顺序**：error 优先于 empty？（失败时给重试而非「去新建」）

任何一条答不上 = 这个页面带 bug，不能交付。
