# 给自己的 SaaS 定价

> ⓪ 竞品分析的 README 承诺过「给定价 / 定位提供锚点」——这份文档就是来承接它的。
> 给非技术 founder：**定价不是拍脑袋，也不是越低越好。** 它是你做的所有决策里**最影响收入、又最容易被做错**的一个。
> 核心一句话：**先看着竞品定一个不离谱的价，上线收钱，再根据真实反馈慢慢调——别一开始就追求"完美定价"。**

---

## 1. 四种常见计费模型（各自适合谁）

定价的第一个决定，是**按什么收钱**。常见的四种：

| 模型 | 怎么收 | 适合谁 | 要小心什么 |
|------|--------|--------|-----------|
| **按人头（按席位）** | 每多一个用户账号，每月加一份钱 | 团队协作类工具（一个公司多人用，示例：协作 / CRM / 项目管理） | 客户会想办法"共用一个账号"省钱；要让多账号确实更好用 |
| **按用量** | 按实际使用量收（条数 / 次数 / 容量） | 用量差异很大的工具（示例：发短信、存文件、跑接口） | 客户**算不清这个月要花多少**会不敢用；要给个用量预估器 / 封顶 |
| **分层订阅** | 分几个套餐档（基础 / 专业 / 旗舰），每档功能 + 价格递增 | 大多数 SaaS 的默认选择 | 档分太多 = 客户选择困难；2-3 档最好 |
| **免费增值（Freemium）** | 有个永久免费档，高级功能 / 更大额度才收费 | 靠"先用上瘾再付费"获客的产品 | 免费档给太多 = 没人付费；给太少 = 没人留下。免费档边界是生死线 |

> 多数早期 SaaS 的稳妥起点是**分层订阅（2-3 档）**，必要时叠加"按人头"。先别上"按用量"——它对你和客户都最难算清。

---

## 2. 怎么定免费档（Freemium）的边界

如果你打算做免费档，**免费给到哪、从哪开始收费**是整个定价里最难、最关键的一刀。

判断原则：**免费档要让人"用得爽到离不开"，但"一旦认真用就会撞到墙"。**

- ✅ 好的免费档：核心功能能用、能完成一次完整价值闭环，但**额度 / 高级能力**留给付费档（示例：免费版能管 50 个客户，认真做生意的公司很快就不够用）。
- ❌ 坏的免费档之一：免费版啥都给全 → 没人有理由付费。
- ❌ 坏的免费档之二：免费版残废到走不完一次流程 → 用户还没体会到价值就走了。

**给 founder 的体感测法**：问自己——「一个**真用我产品做生意**的客户，会在第几天撞到免费档的墙？」答案应该是「很快、而且撞得心甘情愿（因为已经尝到甜头）」。如果答案是「永远撞不到」，免费档边界给太松了。

## 3. 怎么用竞品定价做锚点

这是 ⓪ 竞品分析直接喂给你的弹药。**不要凭空想一个数字，去看竞品挂多少。**

1. **拉一份竞品价目表**：找 3-5 个最像你的竞品，把它们的套餐档 + 价格 + 每档给什么，抄进竞品对比矩阵（见 [`competitive-matrix-template.md`](competitive-matrix-template.md)）。
2. **找出"行业锚点价"**：同类产品的主力档大致落在什么区间——这就是客户心里的"这类东西大概值多少"。你的价偏离这个区间太远（无论高低）都需要一个理由。
3. **用差异化决定你站哪**：
   - 你比竞品**多解决了一个痛点** → 可以贴着锚点或略高，把差异化讲清楚。
   - 你是**更轻、更便宜的替代** → 站在锚点下方，但别低到"看起来很廉价 / 不可信"。
   - 你**正面对标大厂** → 一般不靠低价赢（你扛不起价格战），靠某个细分做得更好。

> 关键认知：**客户判断"贵不贵"，是拿你和竞品比，不是看你的成本。** 所以锚点来自市场（竞品），不来自"我做这个花了多少"。

## 4. 定价常见错误（founder 最容易踩的三个）

1. **定太低**（最常见）。
   - "先低价吸引用户，以后再涨" → 低价吸来的常是**对价格最敏感、最难伺候、最先流失**的客户；而且**涨价比定高了往下调难得多**。
   - 低价还会传递"我的产品不值钱"的信号，反而劝退真正愿意付费的优质客户。
   - 解药：宁可**开始定得略高 + 给一个折扣**，也不要一开始就标个低价。

2. **一开始就把定价做得很复杂**。
   - 五个套餐 + 一堆加购项 + 按用量阶梯 → 客户**算不明白要花多少就不会买**。
   - 解药：第一版**越简单越好**（2-3 档，一眼看懂）。复杂度等有真实数据了再加。

3. **不敢涨价 / 永远不调价**。
   - 产品越做越好、成本越来越高，价格却三年不动 → 等于在持续打折。
   - 老客户怕涨价跑掉 → 可以**只对新客户涨**，老客户保留老价一段时间（这叫"祖父价"）。
   - 解药：把"定期复看定价"当成例行动作，而不是一锤子买卖。

---

## 5. 什么时候该调价

不是定完就一劳永逸。出现下面任一信号，就该认真复看定价：

- **几乎没人嫌贵 / 成交太顺** → 可能定低了，留了钱在桌上。
- **大量客户卡在"差一点就买"** → 可能某个档的价 / 功能切分不对。
- **你给产品加了重磅新功能** → 新价值没反映到价格上。
- **成本结构变了**（示例：依赖的外部服务涨价，见 [`../4-architecture/README.md`](../4-architecture/README.md) founder 视角第 3 问）。
- **每季度 / 每次大版本前的例行复看**（呼应竞品分析"结论有时效，要定期复看"）。

> 调价原则：**对新客户调价随时可做；对老客户调价要给缓冲**（提前通知 + 老价保留期），别突然伤了已经信任你的人。

## 定价决策清单（照着填一遍再上线）

动手设定价格前，把下面这几条逐条想清楚——哪条答不上来，定价就还没准备好：

- [ ] **收费模型**：按人头 / 按用量 / 分层订阅 / 免费增值，选了哪个？为什么？
- [ ] **竞品锚点**：3-5 个竞品的主力档价格区间是多少？我落在区间的哪个位置、凭什么？
- [ ] **档数**：套餐是不是 ≤3 档、一眼看得懂？（多了就砍）
- [ ] **免费档边界**（如果做）：一个认真用的客户多久会"心甘情愿地撞到墙"？
- [ ] **没人嫌贵怎么办**：万一成交太顺，我的涨价路径是什么？
- [ ] **涨价预案**：以后涨价，老客户怎么过渡（祖父价 / 缓冲期）？
- [ ] **复看节奏**：下一次复看定价是什么时候？（建议每季度 / 每次大版本前）

> 最后提醒：**第一版定价一定不完美，这很正常。** 定价是个持续调整的过程，不是一次性的考试。先定一个不离谱的价、开始收钱、收集真实反馈，比纠结到"完美"再上线强得多。
