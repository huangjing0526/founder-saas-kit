# 交互约定（Interaction Conventions）

> 一句话：把高频界面交互**一次性约定死**——列表页长什么结构、新增/编辑用什么容器、操作列怎么收、长文本怎么处理、空态用什么。约定统一后，用户每个页面不用重新学，开发不用每页重新拍板。
> 框架无关，每条讲「约定是什么 + 为什么」；只有标注「（实现示例）」处才落到具体组件，真实写法见 [`examples/ui-baseline.example.md`](../../examples/ui-baseline.example.md)。

---

## 1. 列表页固定结构

**约定**：所有列表页用同一套从上到下的结构骨架：

```text
[ 工具栏：搜索 + 筛选入口 + 主操作按钮 ]
[ （可选）统计卡片：点击即筛选 ]
[ 筛选栏 / 已选条件 ]
[ 表格 / 列表（统一行高、统一三态） ]
[ 分页 ]
```

**为什么**：列表是 SaaS 里最高频的页面类型。结构统一后，用户在任何模块（客户 / 订单 / 商机…）的列表都「在同一个地方找搜索、同一个地方找筛选、同一个地方翻页」——肌肉记忆迁移，学习成本归零。开发也不用每个列表重新决定布局。

**配套约定**：
- 统计卡片**点击即筛选**——点一张卡就把对应筛选条件应用上并刷新列表，当前生效的卡高亮。纯展示型数字卡可不点。
- 列表三态（loading / empty / error）按 [`three-states.md`](three-states.md) 处理，最好封进列表骨架组件，不每页手写。

---

## 2. 新增 / 编辑用「右侧抽屉」而非「弹窗」

**约定（PC 端）**：列表页内的新增 / 编辑入口，一律用**右侧滑出抽屉**，不用居中模态弹窗。宽度按内容密度选最小够用的档位（简单表单窄、复杂表单宽，有上限），超过上限就改成独立页面。

> 移动端对应的是**底部抽屉**（bottom sheet），不是右侧——这是分治法里各端各自的落地（见 [`README.md`](README.md) 第 3 节）。下面讲的「为什么」两端通用。

**为什么抽屉优于弹窗**：
- **不打断上下文**：抽屉从侧边滑出，列表仍在视野里，用户知道自己在哪、在编辑哪一行；居中弹窗把整个列表盖住，容易迷失。
- **容得下复杂表单**：抽屉可以做长、做宽、内部滚动；弹窗一长就变成「弹窗里再滚动」的糟糕体验。
- **交互一致**：所有「新增/编辑」都从一个方向滑出，行为可预期。
- **弹窗留给真·瞬时确认**：删除确认、简单提示这类「一句话决策」才用弹窗。

**配套约定**：
- 抽屉关闭时销毁内容（destroy-on-close 思想），避免下次打开残留上次的脏数据 / 校验态。
- 宽度有上限——内容密度超过抽屉能承载的，改独立页面或分栏布局，**别把抽屉撑成全屏弹窗**。

---

## 3. 操作列：主操作 ≤2，其余收起

**约定**：表格行内的操作按钮，**最多平铺 2 个主操作**（如「详情」「编辑」）；第 3 个及以后**收进「更多」下拉**。

**为什么**：
- 行内平铺 3+ 个按钮，列宽爆炸、视觉嘈杂，每行都是一排按钮抢注意力。
- 主操作 ≤2 把「最常用的」直接给到，长尾操作（删除、转移、导出…）收进「更多」，既不挤又不丢功能。
- 「更多」触发器文案、行内按钮文案全走 i18n（「更多 / 详情 / 编辑 / 删除」），禁硬编码——多语言完整性红线。

> 移动端对应的是**长按弹出动作表**（action sheet）收纳长尾操作，思想一致：主操作露出、长尾收纳。

---

## 4. 单行省略 + 悬停 tooltip

**约定**：表格 / 列表单元格里的长文本，**单行截断省略号**，不换行不撑高；**悬停（或长按）展示完整内容**（tooltip）。

**为什么**：
- 行高一旦被长文本撑开，每行高度参差，列表节奏全乱、密度骤降、扫读困难。
- 单行 + 省略保证行高统一、信息密度可控；tooltip 兜底「想看全的能看全」，不丢信息。
- 禁止在单元格里塞多行块（多段文字 / 多行 div）撑高行——这是列表最常见的破相。

---

## 5. 空状态用统一组件，不自画

**约定**：所有空态用**一个统一的空态组件**，不允许每个页面自画空图 / 自拼空提示。文案走 i18n。

**为什么**：
- 空态是最常被「顺手新建」的件（见 [`component-reuse-redline.md`](component-reuse-redline.md)）——五个页面五套空图，视觉立刻不一致。
- 统一组件保证四件套齐全（图标 + 标题 + 说明 + 可选 CTA），不会有人偷懒只放一行字。
- 详见三态文档 [`three-states.md`](three-states.md) 的 Empty 部分。

## 6. 其它通用约定（简表）

| 约定 | 是什么 | 为什么 |
|---|---|---|
| 状态标签统一配色映射 | 状态 chip 的颜色从一处统一映射取（成功=绿、警告=黄、进行中=蓝、危险=红、中性=灰），禁组件内各写各的 | 同一种状态在全站颜色一致，用户一眼识别 |
| 按钮主次分明 | 一个区域只有一个主按钮（强调色），其余次要 / 文字按钮 | 引导用户视线到「最该点的那个」 |
| 异步操作给 loading | 提交 / 删除等异步操作期间，按钮进 loading 态、禁重复点 | 防重复提交，给「正在处理」反馈 |
| 反馈用非阻塞提示 | 成功 / 失败用 toast，不用挡住操作的弹窗 | 不打断流程 |
| 列表返回保留态 | 列表→详情→返回时，保留之前的 tab / 筛选 / 滚动位置 | 用户翻到第 5 页点进详情，返回还在第 5 页，不被打回顶部 |
