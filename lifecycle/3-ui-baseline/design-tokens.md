# 设计 Token 体系（Design Tokens）

> 一句话：**界面里的颜色 / 间距 / 字号 / 圆角 / 阴影，一律走「命名的 token 变量」，绝不写死字面量。**
> 本文讲思想（框架无关）+ 怎么给自己项目建一套，不绑任何具体变量名。具体变量名见 [`examples/ui-baseline.example.md`](../../examples/ui-baseline.example.md)。

---

## 1. 红线：禁硬编码视觉常量

❌ 禁止在页面 / 组件里写死这些字面量：

- 颜色（`#7257F5`、`rgb(...)`、`red`）
- 间距（`margin: 13px`、`padding: 20px` 凭手感拍的数）
- 字号（`font-size: 15px`）
- 圆角 / 阴影（`border-radius: 11px`、手写 `box-shadow`）

✅ 必须改成引用一个**命名 token**：用「主色 token」「中等间距 token」「正文字号 token」这类语义名，而不是裸数值。

> 「禁硬编码」不是洁癖。它是下面所有能力（主题切换、暗黑模式、RTL、品牌定制）的**前提条件**。

---

## 2. 为什么（这是本文的核心）

| 不用 token 的代价 | 用 token 后 |
|---|---|
| 主色要从紫改成蓝 → 全仓库 grep `#7257F5` 改几百处，必漏 | 改一个 token 定义，全局生效 |
| 想做暗黑模式 → 每个写死的颜色都得手动配深色版，做不动 | 一套 token 切两套值，整站自动切换 |
| 想支持 RTL（阿拉伯语等右到左）→ 写死的 `margin-left` 全是坑 | 用「起始侧 / 结束侧」语义 token，方向自动翻转 |
| 多租户想各自换品牌色 → 没法做 | token 按租户注入，一处接管 |
| 间距凭手感（13px / 17px / 21px）→ 页面节奏乱、不一致 | 间距只能从网格档位里选，天然对齐 |

**一句话记忆：token 是「改一处全局生效」的开关；硬编码是「改一处只改了那一处」的债。**

---

## 3. 间距走 4px / 8px 网格

间距（margin / padding / gap）**不允许出现任意数值**，只能从一组固定档位里选，档位以 **4px 为基本单位**（密集界面）或 **8px 为基本单位**（宽松界面）递增：

```text
4px 网格示例档位：4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 ...
```

给每个档位一个语义名（xs / sm / md / base / lg / xl ...），代码里只引用语义名。

**为什么要网格**：
- 视觉节奏统一——所有间距都是 4 的倍数，元素自然对齐，不会出现 13px 挨着 17px 的别扭。
- 决策成本归零——写界面时不用纠结「这里留多少」，从档位里挑一个最近的即可。
- 跨人/跨 AI 一致——不同人写的页面间距能对上。

> 反例：`gap: 10px`（不在 4px 网格上）、`padding: 15px 18px`（凭手感）。
> 正例：引用「中等间距 token」「基础间距 token」，其值落在网格档位上。

---

## 4. 一套 token 通常分这几类

给自己项目建 token 时，按语义分类（名字自己定，下面是**思想分类**，不是变量名）：

| 类别 | 包含 | 命名建议 |
|---|---|---|
| **品牌色** | 主色 + hover 态 + 浅色态 | 语义名（primary / primary-hover），不是 `purple` |
| **状态色** | 成功 / 警告 / 危险 / 中性，每个配「前景 + 浅背景」一对 | success / warning / danger / info，各带 `-bg` |
| **中性色** | 文字（主/次/弱/占位）、边框（常规/浅）、背景（页/卡/hover） | 按用途命名，不是按深浅命名 |
| **间距** | 4px 网格的一组档位 | space-xs / sm / md / base / lg / xl ... |
| **字号** | 一组阶梯（正文为基准，上下各几档） | font-xs / sm / base / lg / xl ... |
| **圆角** | 卡片 / 按钮 / 标签各自的圆角 | radius-card / radius-btn |
| **阴影** | 卡片 / 浮层的层级阴影 | shadow-card / shadow-popover |
| **过渡** | 快 / 中 / 慢三档动画时长 | transition-fast / base / slow |

**关键原则——按「用途」命名，不按「外观」命名**：
- ✅ `--color-text-secondary`（次要文字）→ 哪天次要文字从灰改成别的颜色，语义不变。
- ❌ `--color-gray-500`（灰色 500）→ 一旦不灰了，名字就骗人，全站要改名。

---

## 5. 落地要点

- **一处权威来源**：token 定义集中在一个文件 / 一个配置块（注释里写明「这里是唯一权威，代码引用以此为准」）。
- **状态色配成对**：每个状态色配一个「前景色 + 浅背景色」对，标签 / 提示框直接取这对，保证对比度（建议过 WCAG AA）。
- **暗黑 / RTL / 主题留接口**：token 用变量机制定义（具体机制看你的栈 ——（实现示例）见 example），同一组语义名能切换多套值，是后续做暗黑 / 多主题的唯一可行路径。
- **token 不够用先扩档位，不要破例硬编码**：发现没有合适间距档位，是去扩充档位表，不是在页面里写死一个新数值。
