# Founder 周检 5+5

> 每周五 30 分钟。任何一项异常 = 当周修，不进下周。
> AI 实施细则在最底部，founder 不需要看那一段。

## 5 个数字（AI 每周五早上自动报）

| 指标 | 大白话含义 | 红线 | 红了怎么办 |
|---|---|---|---|
| 测试通过率 | 上次能用的功能这次还能不能用 | < 100% | 让 AI 立刻修到全绿，绿了才能上线 |
| 待确认业务规则数 | 还没你拍板的"自动行为 / 校验"挂在系统里 | > 5 条 | 让 AI 一条条解释，逐条 OK / 撤销 |
| 死代码增量 | AI 有没有偷懒乱堆没人用的代码 | 本周 > 0 | 让 AI 删掉或解释为什么留 |
| 加载速度变化 | 用户打开页面变没变慢 | 比上周慢 | 让 AI 找出哪个改动让它变慢 |
| 生产 error 增量 | 用户用着报没报错 | 比上周多 | 让 AI 拉日志找原因 |

Founder 不需要看技术细节——AI 给 yes/no 或趋势数字，看趋势就行。

## 5 个手测路径（founder 周五自己点 15 分钟）

打开浏览器，假装你是各类用户。能用顺 = 通过；卡顿 / 报错 / 不对劲 = 让 AI 修。

1. **登录 + 看首页/Dashboard**——任何用户最先做的事
2. **打开核心列表 → 点开一条 → 改一个字段 → 保存**——用户日常 80% 的操作
3. **越权/数据隔离验证（多租户项目专属）**——用 A 账号登录，URL 把资源 ID 改成 B 账号名下的某条记录 → 必须看不到（数据隔离硬红线）。单租户项目改为：用低权限账号访问只有管理员能看的资源 → 必须被拦
4. **逐个切支持的语言（zh / en / ...）**——切到每种语言后看核心页面是不是 100% 那种语言，有没有混入其他语言或缺翻译退化字段
5. **本周改过的功能走一遍**——按 AI 给你的"上线说明"逐项验

### 附加观察项（不算核心数字，顺手看一眼）

- **反馈池积压**：扫一眼用户反馈池——有没有积了一堆没分诊的、有没有做完了忘回告用户的（闭环的最后一步最容易漏）。不红线、不强塞进 5 个数字，但每周顺带看一眼，反馈才不会在池子里烂掉。完整闭环见 [`../business/feedback-loop.md`](../business/feedback-loop.md)。

## 红了怎么甩回 AI

直接发一句：

> "周检红了第 X 项，你来：1) 怎么回事 2) 修要多久 3) 这周内能不能修完"

AI 必须大白话回，看不懂让它重讲。

## checklist 自身的维护

- 每月底 review 一次：5 个数字 / 5 个路径有没有要换的（业务变了 checklist 要跟着变）
- 新页面上线后：在路径 4 加一项
- 数字红了 3 周以上还修不完 → 升级到 sprint 待办，不是"周检"层面能解决的了

## 实施细则（AI 实施用，founder 不需要看）

### 5 个数字采集命令

> 命令按本仓库技术栈替换。下面是一套 JS/Node 项目的参考实现。

```bash
# 1. 测试通过率（用一次性 run 而非 watch 模式，后者会挂住）
npm run test:run 2>&1 | tail -10

# 2. 待确认业务规则数（业务规则总账里 [待确认] 计数）
grep -c "\[待确认\]" docs/business-rules-registry.md

# 3. 死代码增量（纯 JS+前端框架项目用 knip，TS 项目可用 ts-prune）
npx knip --no-progress --no-exit-code > /tmp/knip-$(date +%Y%m%d).txt
grep -E "^(Unused|Duplicate)" /tmp/knip-$(date +%Y%m%d).txt
# 环比看 Unused files / Unused exports 两个数是否上涨

# 4. 加载速度（dist 体积代理指标）
npm run build && du -sh dist/

# 5. 生产 error 增量（最近 7 天，经进程管理器拉错误日志计数）
ssh <prod-host> '<进程管理器> logs --err --lines 5000 --nostream' | grep -c ERROR
```

### 周检报告格式（贴给 founder 的样子）

```
本周（YYYY-MM-DD）周检 5 个数字：
1. 测试通过率：100%（vs 上周 100%）✅
2. 待确认业务规则：3 条（vs 上周 4 条）✅
3. 死代码增量：+0 文件（vs 上周 +2）✅
4. dist 体积：4.2MB（vs 上周 4.1MB，+2.4%）⚠️
5. 生产 error：12 次/7天（vs 上周 8 次）❌

⚠️/❌ 项的大白话解释 + 建议：
- ⚠️ 加载速度：本周新增 X 功能引入 Y MB 依赖，建议 Z 处理
- ❌ 生产 error：error 集中在 /api/<某接口>，看起来是 <某变化> 导致 ...
```

### 触发节奏

- 周检由 founder 主动 ask（暂不自动）：founder 说"跑周检"或"weekly check" → AI 立即采集 + 给报告
- 后续如要自动化：在调度配置里配 cron（待定）

> ⚠️ **诚实说明**：这个节拍靠纪律，**kit 本身不含任何自动调度**——不会到点自动提醒你跑周检，也不会自动生成报告推给你。「AI 每周五早上自动报」指的是"你叫它跑，它当场采集"，不是有人替你定时触发。真要强制（到点必跑、不靠你记），自己挂一个 cron / CI 定时提醒，做法见 [`../../engineering/governance-skills/S10-ops-automation-cron-workflow.md`](../../engineering/governance-skills/S10-ops-automation-cron-workflow.md)。
